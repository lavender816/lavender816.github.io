Shoka主题：实现桌面歌词展示效果

发表于 2026-08-19 本文字数 19k 字 阅读时长 17 分钟
  • Lavender's Blog
首页 SHOKA

为 Shoka 右下角音乐播放器加入默认开启的桌面歌词开关，将当前 LRC 歌词以主题色浮层显示在屏幕底部，并同步播放、暂停、拖动进度、切歌和刷新后的状态。

#前言

Shoka 播放器原本可以在音乐面板内部滚动显示歌词，但关闭面板后就无法继续看到当前歌词。本次改造会复用播放器已有的 LRC 解析结果，在页面底部增加一条独立的桌面歌词浮层。

最终效果包含：

  • 在音乐面板控制栏中加入桌面歌词按钮；
  • 默认开启，用户关闭后记住选择；
  • 当前歌词显示在屏幕最下方；
  • 使用主题色文字、半透明背景和模糊效果提高可读性；
  • 播放时显示，暂停时自然隐藏；
  • 拖动进度条时立即同步歌词；
  • 切歌后重新解析新歌曲的 LRC；
  • 无歌词时不会显示空浮层；
  • 支持日间 / 夜间模式、移动端和减少动态效果设置；
  • 支持键盘操作与基础无障碍属性。

#开始前准备

  1. 找到博客根目录，并备份 themes/shoka/source/js/_app/player.js 与 themes/shoka/source/css/_common/components/tags/player.styl ；
  2. 确认右下角音乐播放器已经可以正常打开、播放和切歌；
  3. 至少准备一首带 LRC 歌词的音乐；
  4. 如果歌单由 Meting 接口返回，先确认返回对象中存在 lrc 字段；
  5. 本功能不需要安装新依赖；
  6. 修改完成后通过 hexo server 测试，不要直接编辑 public 目录。

桌面歌词依赖带时间标签的 LRC，例如 [01:23.45]歌词内容 。只有纯文本、没有时间标签的歌词无法跟随播放进度切换。

#常见问题

#播放器有歌曲，但底部没有歌词

先检查当前歌曲对象是否存在 lrc 字段，再检查 LRC 是否带时间标签。只有普通歌词文本时，程序无法知道每一句应该在什么时间显示。

#网络歌词请求失败

在控制台检查 URL、HTTPS 和 CORS。GitHub Pages 使用 HTTPS，HTTP 歌词地址可能被浏览器当作混合内容拦截。

#歌词时间不准确

这是 LRC 文件时间轴的问题。播放器按 LRC 中的时间切换，不会自动识别人声。需要修改歌词文件中的时间标签。

#切歌后仍显示上一首歌词

确保 lyrics.create() 开头记录了当前 playlist.index ，异步回调中再次比较索引；切歌时也要先清空 currentText 并调用 syncOverlay() 。

#歌词挡住移动端按钮

检查 +tablet-mobile() 是否把 bottom 提高到约 3.15rem 。如果网站底部还有其他固定组件，可以继续适当增加该值。

#刷新后开关状态没有保留

确认项目的 store 工具可以正常访问浏览器存储，并检查隐私模式或浏览器的跟踪防护是否禁止了本地存储。
